# Architecture

## Constraints
- Static hosting only (GitHub Pages). No backend, accounts, analytics or network
  calls after load. `validators/app_check.py` and `tools/app_bundle.js` both
  reject `fetch`/XHR/trackers/external resources.
- Ships as **one self-contained HTML file** per build. The embedded Quicksand
  Bold font is a `data:` URI (generated by `tools/embed_font.py`).
- Plain JavaScript, no framework, no dependencies. `tools/app_bundle.js`
  concatenates `app_src/` in filename order into classic scripts. It does not
  resolve ES modules, so every file attaches to `window.App`.

## Layers (filename order = load order = dependency order)
```
app_src/
  router.js                 hash router + nav; re-renders current view on store change
  modules/
    00_core_money.js        integer-cents parse/format, currency list
    01_core_dates.js        local "YYYY-MM-DD" date math (DST-safe, month-end anchoring)
    02_core_schema.js       state shape, version, sanitize()/migrate() for untrusted blobs
    03_core_storage.js      the ONLY localStorage access: load/recover/debounced save
    04_core_store.js        single state tree, named actions, subscribe, one-level undo
    05_logic_bills.js       schedules: nextAfter, rollForward, occurrencesBefore, set-aside
    06_logic_safe_to_spend  THE formula (pure: state, today -> breakdown)
    07_logic_debt_waitlist  payoff ordering, APR parsing, 48h timing
    08_actions.js           every state change; validation -> ValidationError(field, msg)
    ── UI below this line ──
    10_ui_dom.js            h() DOM builder, icons, fields, dialogs, toasts
    20_view_today.js … 25_view_settings.js
  main.js                   boot: storage -> store -> theme -> shell -> router
  styles/00_font … 06_views design tokens -> base -> components -> layout -> views
```
- **Pure core (00–08)** has no DOM access. Node tests load these exact files
  into a `vm` context (`tests/unit/_load.js`), so the shipped code is what gets
  tested.
- **Single source of truth for calculations**: Today, Bills, the Wait List's
  "buying it leaves …" line and nav badges all call
  `App.core.safeToSpend.compute` and `App.core.bills.*`. No view does its own
  arithmetic.
- **Unidirectional flow**: view → `App.store.dispatch(name, rawFormValues)` →
  the action parses/validates/mutates a deep copy → commit → debounced save →
  subscribers re-render. A throwing action leaves state untouched. Forms show
  `ValidationError.field` next to the matching `.field[data-field]`.
- **Derived data is never stored**: the number, future bill occurrences, overdue
  status and debt order are all computed on render.
- **No string-built markup with user data**: every view builds DOM through
  `h()` with `textContent`, so names like `<img onerror>` are inert.

## Persistence and resilience
- Keys: `adhd-safe-to-spend:v1` (full) and `adhd-safe-to-spend-demo:v1` (demo).
  They are distinct because the demo, the full app and this account's other
  Pages apps share one `github.io` origin.
- Load → `JSON.parse` → `schema.sanitize`. Corrupt or unreadable data is copied
  to `<key>:recovery` and reported in a banner, never silently discarded.
  Malformed items are dropped individually and counted ("Some saved items
  couldn't be read"). Data from a newer schema is refused and preserved.
- Writes are debounced (250 ms) and flushed on `pagehide`/hidden. Quota errors
  are reported with a toast, not thrown.
- Import runs the same `sanitize()` and shows a confirm dialog with counts before
  replacing anything.
- Paid bill cycles whose due date has passed roll to the next cycle at boot and
  when the app returns to the foreground on a new day.

## Builds and delivery
`./build.sh` produces:
- `deploy/index.html` — full build (`APP_DEMO_MODE=false`) plus PWA sidecars
  from `tools/app_pwa.py` (manifest, `sw.js`, icons redrawn by
  `tools/make_icons.py`).
- `demo/demo.html` — demo build (`APP_DEMO_MODE=true`), no PWA.

Hosted per `.claude/skills/etsy-deploy/SKILL.md`: the demo at `/`, the full build
at `/app-574278ef/`. Service worker: network-first for the page (redeploys reach
installed users), cache fallback offline, cache name versioned by build hash,
and old caches deleted on activate.
